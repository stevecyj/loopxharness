# Workflow：把學習成果轉成 blog

新增或更換課程時，直接把材料放進 `課程材料/` 即可，不必手動修改本檔的檔名；產出對應表由 Agent 執行後自動維護。

## 固定設定

| 欄位     | 值                                        |
| -------- | ----------------------------------------- |
| 提示詞   | `prompts/blog/把學習成果轉成blog.md`      |
| 材料目錄 | `課程材料/`（搭配 `output/預期學習成果/`） |
| 輸出位置 | `output/blog/<依文章內容取的繁中檔名>.md` |

## 產出對應表

| 原始課程筆記／逐字稿                                 | Prompt 1：進階學習筆記                                             | 我的實作經驗或想法 | Blog 輸出路徑                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------ | ------------------ | -------------------------------------------------------------------- |
| `課程材料/introduction to ai for web developers.md` | `output/預期學習成果/網頁開發者的 AI 入門.md`                      | （無）             | `output/blog/採用率不等於成效：怎麼讀 AI 開發工具的數據.md`          |
| `課程材料/從動機到持續行動-使用者提供逐字稿.md`      | `output/預期學習成果/驗證-20261020-正常-第5次-從動機到持續行動.md` | （無）             | `output/blog/驗證-20261020-正常-第5次-把行動接上固定線索.md`         |
| `課程材料/驗證-戰術性壓力-原文節錄.md`               | `output/預期學習成果/驗證-20261020-特殊-第5次-戰術性壓力的限制.md` | （無）             | `output/blog/驗證-20261020-特殊-第5次-如何判讀成功經驗的適用範圍.md` |

## 執行方式

1. 先讀取並遵守 `docs/project-constitution.md`，再讀取「提示詞」及其引用的 Standard Card（`standard-cards/blog/把學習成果轉成blog.md`）。
2. 掃描 `課程材料/`（或使用者指定的材料），對照上方「產出對應表」與 `output/blog/` 內的實際檔案：
   - **已有學習筆記、尚無對應 Blog 輸出**：讀取對應的「Prompt 1：進階學習筆記」、「原始課程筆記／逐字稿」與「我的實作經驗或想法」（標示「（無）」視為未提供），產出 Blog 並通過 Standard Card 驗收後寫入 `output/blog/<依文章內容取的繁中檔名>.md`。
   - **已有對應 Blog 輸出**：先向使用者確認「該材料已有對應的 Blog 輸出，是否要重新跑一次流程（覆蓋既有輸出），還是跳過？」，經使用者確認重跑後才執行。
   - **尚無對應的學習筆記**：依專案憲法停止串接或先執行 `workflow/預期學習成果/workflow-重建學習成果.md`，完成學習筆記後再執行本 workflow。
3. 寫入完成後，由 Agent 自動將實際產出路徑更新至本檔的「產出對應表」。
