# Workflow：把學習成果轉成 blog

新增或更換課程時，直接把材料放進 `課程材料/` 即可，不必手動修改本檔的檔名；產出對應表由 Agent 執行後自動維護。

## 固定設定

| 欄位     | 值                                        |
| -------- | ----------------------------------------- |
| 提示詞   | `prompts/blog/把學習成果轉成blog.md`      |
| 材料目錄 | `課程材料/`（搭配 `output/預期學習成果/`） |
| 輸出位置 | `output/blog/<依文章內容取的繁中檔名>.md` |

## 產出對應表

| 原始課程筆記／逐字稿                                 | Prompt 1：進階學習筆記                                                      | 我的實作經驗或想法 | Blog 輸出路徑                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------- | ------------------ | -------------------------------------------------------------------- |
| `課程材料/introduction to ai for web developers.md` | `output/預期學習成果/網頁開發者的 AI 入門.md`                               | （無）             | `output/blog/採用率不等於成效：怎麼讀 AI 開發工具的數據.md`          |
| `課程材料/從動機到持續行動-使用者提供逐字稿.md`      | `output/預期學習成果/驗證-20261020-正常-第5次-從動機到持續行動.md`          | （無）             | `output/blog/驗證-20261020-正常-第5次-把行動接上固定線索.md`         |
| `課程材料/驗證-戰術性壓力-原文節錄.md`               | `output/預期學習成果/驗證-20261020-特殊-第5次-戰術性壓力的限制.md`          | （無）             | `output/blog/驗證-20261020-特殊-第5次-如何判讀成功經驗的適用範圍.md` |
| `課程材料/ViteConf 2026.md`                          | `output/預期學習成果/ViteConf 2026：AI 代理時代的前端工具鏈與生態系演進.md` | （無）             | `output/blog/當 AI 代理接手開發迴圈：用四個步驟檢查專案的驗證速度與決定性.md` |
| `課程材料/想成功，得有點不切實際.md`                 | `output/預期學習成果/用不切實際的目標重塑注意力與行動.md`                   | （無）             | `output/blog/行事曆排滿卻還在原地：用三個步驟跳出線性目標與無效忙碌.md`       |

## 執行方式

1. 先對照上方「產出對應表」，並用檔案清單工具列出 `課程材料/`、`output/預期學習成果/` 與 `output/blog/` 的檔名（此階段只比對檔名，**不要讀取任何材料或筆記的檔案內文**，以免檔案數量多或篇幅長時讓使用者空等），向使用者回報最新盤點結果並確認本次要處理的材料：
   - **已有對應 Blog 輸出**：詢問使用者是否要重新執行並覆蓋，還是跳過。
   - **已有學習筆記、尚無對應 Blog 輸出**：列出待轉成 Blog 的項目，確認是否直接以既有學習筆記接續產出，或從學習成果重新跑起。
   - **尚無對應的學習筆記**：告知使用者需先執行 `workflow/預期學習成果/workflow-重建學習成果.md` 完成學習筆記後，再執行本 workflow。
2. 經使用者確認本次要執行的材料清單後，讀取並遵守 `docs/project-constitution.md`、本檔指定的「提示詞」與對應 Standard Card（`standard-cards/blog/把學習成果轉成blog.md`），再只讀取本次要處理項目的「Prompt 1：進階學習筆記」、「原始課程筆記／逐字稿」與「我的實作經驗或想法」（標示「（無）」視為未提供），產出 Blog 並通過 Standard Card 驗收後寫入 `output/blog/<依文章內容取的繁中檔名>.md`。
3. 寫入完成後，由 Agent 自動將實際產出路徑更新至本檔的「產出對應表」。
