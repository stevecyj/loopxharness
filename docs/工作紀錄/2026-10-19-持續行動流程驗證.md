## 規則版本與執行方式

- 依 `docs/流程驗證.md` 執行，原 workflow 僅供讀取；以上設定取代本次輸入與輸出。Blog 使用同案例通過的學習成果，直接傳路徑，不寫回正式 workflow。
- 本次規則有未提交修改。起始 HEAD、正式檔案雜湊與輸入雜湊見 `2026-10-19-持續行動流程驗證附件/manifest.json`，完整規則快照見同附件的 `規則快照/`。
- 使用者已明確決定：學習成果依材料實際支持的數量，只有 1～2 個就寫 1～2 個。這是本次執行的已授權要求，不放寬 Standard Card，不為湊數添加論點。
- 兩個案例分別用全新 Claude Code Session 執行，只交付程序與本紀錄路徑及案例名稱。主 Agent 再獨立對照原文、產出及兩張卡複核。Session 證據於實際執行後填寫。
- 不 commit、不修改正式規則、卡與 workflow；若發現指示缺陷，先回報具體問題。產出前逐條檢查；失敗項目、修正與複核另記於本紀錄，不能只留下通過結論。

## 預期

### 正常案例

完成 A～D 學習成果與文章區／寫作過程區的 Blog，兩張卡逐條驗收。

- 保留啟動動機與持續系統的區別、資訊輸入與行動輸出的回饋關係，以及環境、訊號、行為、回饋的具體操作。
- 保留「戰術性壓力不適合所有人」及個人相信會無家可歸、實際並不會的差異；不將個案升格為普遍有效的財務策略。
- 無法確定的名言歸屬與辨識錯誤不得寫成已核實事實；產品功效及對多數人生活狀態的泛化說法不得當成證據充分的結論。
- Blog 的操作寫成可自行執行的步驟與判斷標準，不能捏造已執行的結果或使用者個人經驗。

### 特殊案例

針對 681 字元的限制與自我修正段落，驗證縮小範圍後仍能保留原意。預期可生成短篇學習成果與以成功經驗判讀為主題的 Blog，不要求成果湊到 3 個。

- 保留三個關鍵差異：主觀相信可能無家可歸／隨後澄清實際不會；個人重複嘗試且自認有效／未提供比較數據；方法極端且不適合所有人。
- 筆記不擴寫成原文沒有的風險管理方法。Blog 可作有限延伸，但須用適當確定程度表達，並在寫作過程區區分原文與延伸。
- 不把原文個人成功歸因寫成必然因果，不建議讀者承擔付不起的租金來保證成功。

以上重點分別對應學習成果卡的必要細節、察覺矛盾、不得補造／當成事實，以及 Blog 卡的來源區分、不得虛構、材料不足縮小範圍等條款；不取代其餘卡條文。
