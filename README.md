# loopxharness

這個專案把課程材料依序整理成學習成果與 blog 草稿。`課程材料/` 中的每個檔案代表一份獨立材料，對應一份學習筆記（`output/預期學習成果/`）與一份部落格文章（`output/blog/`）。

## 執行順序

1. **放入材料**：把新的逐字稿或課程材料放進 `課程材料/`（**不必手動去改 `workflow/` 裡的任何檔案**）。
2. **請 Agent 執行 workflow**：直接對 Agent 說以下任一句：
   - **跑全部流程**：「請執行 `workflow/預期學習成果/workflow-重建學習成果.md` 與 `workflow/blog/workflow-轉成blog.md`」（或簡稱「幫我跑 workflow」）
   - **只跑某一份材料**：「幫我用 `課程材料/xxx.md` 跑 workflow」
   - **只跑其中一段**：「幫我跑學習成果 workflow」或「幫我跑 blog workflow」

**Agent 接手後的自動處理：**
- 先讀取 `workflow/` 內的「產出對應表」，並只列出 `課程材料/` 與 `output/` 的檔案清單（確認前不讀材料內文，避免檔案多或篇幅長時等待讀取）。
- 先向你回報目前狀況（哪些是新材料、哪些已有輸出），由你決定本次要處理哪些材料、既有輸出是否覆蓋，並一併詢問是否有想加入的額外課程筆記或個人實作經驗／想法（預設為無）。
- 確認要處理的清單後，Agent 才會讀取規則與目標材料內文，產出學習筆記與 Blog，並在完成後自動把新檔案路徑登記回 `workflow/` 對應表。

## 規則分工

- **Workflow＋提示詞（Spec）**：提示詞定義分析與寫作步驟；`workflow/` 保存「材料 ↔ 學習筆記 ↔ Blog」產出對應表與重跑確認規則。
- **Standard Card**：單次輸出的驗收標準，保存固定條款與訂立原因，不記錄單次 Pass／Fail。
- **[專案憲法](docs/project-constitution.md)**：全專案共享的原則與邊界，包括重跑前確認、部分執行、本次例外與失敗處理。

每份 workflow 都會先比對產出對應表與目錄檔名、向使用者確認本次要處理的材料後，再讀取專案憲法、提示詞、對應 Standard Card 與目標材料內文。一般完整執行時，Agent 寫入前逐條檢查，不符合就修改並重新檢查；部分執行、本次明確例外及無法通過的情況依憲法處理。

反覆修正後確認的要求，經使用者明確指示，更新對應 Standard Card 或專案憲法，作為長期保留的規則。

## 驗證與改善流程

建立流程、首次使用新類型材料，或修改提示詞、workflow 執行方式、專案憲法後，依[流程驗證程序](docs/流程驗證.md)試跑新材料與特殊案例。失敗時先定位原因，修正後重新執行，確認問題解決且原有品質保留。日常產出仍依上面的執行順序，不必每次另跑驗證案例。

開始驗證時，提供另一份課程材料的路徑，請 Agent 執行 `docs/流程驗證.md`。程序會指定驗證用的輸入、輸出與 Blog 銜接路徑，結果另存於 `docs/工作紀錄/`，不覆寫正式設定與既有產出。
