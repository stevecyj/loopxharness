你是一位兼具軟體工程實務、技術寫作與編輯能力的資深作者。

我已經透過 Prompt 1（`prompts/預期學習成果/從課程內容重建學習成果.md`），使用 UbD、Cornell Notes 與 Self-explanation 分析課程內容，產生一份「進階學習筆記」。

**現在請以 Prompt 1 的分析結果為主要依據，進一步尋找 Blog 寫作主題，建立文章架構並產出初稿。**

## 一、輸入資料與使用規則

Prompt 1 的結果包含四個部分：

- **A. 課程核心**：核心問題、預期學習成果、證據與可信程度。
- **B. 進階學習筆記**：核心觀念、原理、講師範例、適用情境與限制。
- **C. 自我驗證**：理解題、應用題、實作題。
- **D. 尚未解決的問題**：知識缺口、延伸研究問題、潛在文章主題。

請依照以下方式使用：

1. 從 A 找出值得分享的能力與核心問題。
2. 從 B 找出能解決讀者問題的知識、方法與案例。
3. 從 C 找出適合文章使用的實作與驗證方式。
4. 從 D 尋找有價值的文章切入角度與延伸議題。

不要把四個部分直接改寫成四個文章章節，而是重新組織成讀者需要的內容。

## 二、第一階段：尋找寫作角度

1. 分析這份材料能幫讀者解決哪些具體問題。
2. 找出值得討論的實務困境、常見誤解、技術取捨或可驗證的觀點。
3. 提出 2 個文章切入角度，說明各自的：
   - 文章標題
   - 目標讀者
   - 核心問題
   - 閱讀價值
   - 可使用的課程知識
   - 可以實作或驗證的內容
4. 選擇證據最充足、最容易實作驗證的角度。
5. 說明推薦理由，以及這篇文章與一般課程摘要有什麼不同。

## 三、第二階段：建立文章架構

先建立思考架構：列出文章要用的通用模式與步驟，各自對應材料裡的哪個實例，以及換成其他資料時要找的對應內容。再依照「問題—解法—驗證—回顧」建立文章大綱，文章依這份架構撰寫。

### 1. 問題
- 讀者在什麼情境會碰到？
- 為什麼值得解決？
- 常見錯誤或誤解是什麼？先寫成換一份資料也成立的通用模式，再用材料裡的具體資料當例子。

### 2. 解法
- 需要理解哪些核心觀念？
- 如何一步一步解決？步驟要能套用到其他同類資料，材料裡的資料用來示範。
- 為什麼採用這個方法？
- 什麼時候不適合使用？

### 3. 驗證
- 如何設計實作或測試？
- 應觀察哪些結果？
- 怎樣才算成功？
- 有哪些反例或限制？

### 4. 回顧
- 這次真正學到了什麼？
- 哪些情境可以套用？
- 還有哪些沒有解決的問題？

## 四、第三階段：產出文章

輸出分成兩區，用 `---` 分隔，文章區在前：

1. **文章區**：一篇完整的技術 Blog 文章，從文章標題開始，依選定的大綱撰寫，使用適合技術 Blog 的自然語氣。
2. **寫作過程區**：以 `# 寫作過程` 開頭，依序寫：
   1. 文章選題分析：兩個切入角度及推薦理由。
   2. 文章定位：目標讀者、核心問題、搜尋意圖。
   3. Markdown 文章大綱：標出每個段落在「問題—解法—驗證—回顧」中的角色。
   4. 思考架構：文章用到的通用模式與步驟，各自對應材料裡的哪個實例，以及換成其他資料時要找的對應內容。
   5. 內容來源區分：文章中哪些是課程有證據支持的知識、哪些是 AI 延伸分析、哪些尚待驗證。
   6. 待補充項目：需要自行實作、查證、測試或加入個人觀點的內容，以及材料不足的缺口。

文章區要能從頭讀到尾，不被思考過程打斷，所以所有思考過程都只寫在寫作過程區。

## 五、驗收標準

輸出必須通過 `standard-cards/blog/把學習成果轉成blog.md` 的每一條標準。寫入輸出前逐條檢查，不符合的地方直接修改，改完再從頭檢查一次，全部通過才寫入。

## 六、輸入材料

Prompt 1 的進階學習筆記、原始課程筆記／逐字稿、我的實作經驗或想法，以及輸出位置，由 `workflow/blog/workflow-轉成blog.md` 提供，請依該檔讀取材料並寫入指定位置。
